# API contract: app and backend

This document lists every backend endpoint the app calls, what the app sends, and what it reads.
The source of truth is `360ghar-backend/docs/openapi.json`. The change list for the current
release is `contract-audit/contract-changelog.md` (workspace root).

- App root: `360-ghar-app/`. Backend root: `360ghar-backend/`.
- `ApiPaths` is in `lib/core/network/api_paths.dart`. The client adds `/api/v1` to every path.
- Contract tests are in `test/contract/`. They parse fixtures that the backend's own Pydantic
  models produced (`test/fixtures/api/*.json`). See [Fixtures and enums](#fixtures-and-enums).

## Rules the client follows

**Errors.** Every non-2xx JSON body is `{"error": {"code", "message", "details"}}`. `details` is
absent when empty. `ApiErrorBody` (`lib/core/network/api_error.dart`) reads it and
`ApiClient.mapHttpError` turns it into a typed failure. The client branches on `code`, never on
`message`.

| Status | App failure | Notes |
|---|---|---|
| 401 | `AuthenticationException` | Keeps the backend code (`TOKEN_INVALID`, `AUTH_HEADER_MISSING`). One forced token refresh and one retry. A 401 that survives ends the session. |
| 403 | `AuthenticationException` | Keeps the backend code. `USER_INACTIVE` ends the session. Any other code is a permission refusal and keeps it. |
| 404, 409 | `NotFoundException`, `ApiException` | The backend code is kept (`PAGE_NOT_FOUND`, `VISIT_CONFLICT`). |
| 422 | `ValidationException` | `details.fields` is a list of `{field, msg, type}`. `field` has a source prefix (`body.`, `query.`). `fieldErrors` maps the name without the prefix to the list of `type` values. The form localizes the `type` (`AGE_RANGE`, `NAME_LENGTH`, `PHONE_REQUIRED`, `PHONE_INVALID`, `missing`). Text in `msg` is not shown. |
| 429 | `RateLimitException` | `Retry-After` in seconds or an HTTP date; 30 s when absent. |
| 5xx | `ServerException` | Safe reads retry with backoff, never sooner than `Retry-After`. |
| transport | `NetworkException` | `TIMEOUT`, `NETWORK_ERROR`, `CANCELLED`. |

**Requests.** The app sends only declared query keys and body keys. An undeclared key is a 422.
`PUT /users/profile` sends `full_name`, `phone`, `date_of_birth` and nothing else. An explicit
`null` clears a nullable field. A datetime goes out as ISO 8601 with a UTC offset. A date-only
field goes out as `YYYY-MM-DD`.

**Responses.** A key the backend always sends is required in the Dart model, so a renamed or
dropped key fails the parse. A key that can be empty is nullable. Money is a JSON number.
Datetimes are UTC with a `Z`; the app converts to local time for display only. Date-only fields
(`available_from`, `date_of_birth`) are read as dates. No REST response has a `success` flag. A
delete answers 204 with no body, and a create answers 201 with the resource.

**Enums.** `lib/core/data/models/wire_enums.dart` is generated by `tool/gen_enums.py` from
`contract-audit/enums.json`. Each enum reads a missing or unknown wire value as `null` and logs
the type. There is no fallback to a real member. The UI shows nothing for a `null`.

**Pagination.** `CursorPage` is `{items, next_cursor, has_more, limit, total}`. The server sends all
five keys. `total` is `null` unless the request sets `include_total=true`. `limit` is 1 to 100.
A cursor is opaque and bound to the filter set. The app passes it back unchanged with the same
filters. A list read that needs every row follows `next_cursor` while `has_more` is true (the
amenity list does). After `INVALID_CURSOR`, the app starts again from the first page.

**Caching.** The server marks authenticated property responses `Cache-Control: private,
no-store` and still sends an `ETag` and `Vary: Authorization`. The client honors `no-store` itself.

- `ETagCache` keys a row by method, URL, auth requirement and the signed-in account scope.
- A `no-store` response is never written, and a stored row for the same key is deleted.
  Feature caches (property detail, feeds, swipe history) check the mark that `markCachePolicy`
  puts on the decoded object.
- Every cache row carries `AppDatabase.cacheSchemaVersion`. A row written under another version
  reads as a miss, so a changed model never replays an old-shape body on a 304. Bump it when a
  cached model changes. The SQLite `schemaVersion` is 2: the upgrade empties the cache table.
- A property snapshot written to disk has no owner, agent or company phone number
  (`PropertyModel.toStorableJson`).
- When an account signs out, `AppDatabase.purgeScope` deletes that account's cache rows and
  drafts. Pending actions stay with their account. A draft that is 30 days old is deleted when
  read.

**Contact data.** `Property.owner_contact` is the owner's number only for the owner and admins.
For everyone else it is the assigned agent's number, else the company number. The app reads it
through `PropertyModel.contactNumber`, never as the owner's number. `Property.agent` is on the
detail route only. A visit's other person is `PublicUserRef {id, display_name, avatar_url}`.

The bare `GET /agent/conversations/{id}/messages` route is removed (404). The app has no fallback to it.

**Assistant stream.** `POST /agent/chat` answers `text/event-stream`. `AssistantFrame.fromEvent`
reads each frame strictly:

| Frame | Keys | App behavior |
|---|---|---|
| `conversation_info` | `conversation_id` | Stores the id. |
| `text_chunk` | `text` | Appends to the reply. |
| `tool_call_start` | `call_id`, `tool` | Adds the call to the indicator, keyed by `call_id`. |
| `tool_call_end` | `call_id`, `tool`, `success` | Removes only that call. `success: false` marks the reply as incomplete. |
| `widget` | `widget_name`, `structured_content` | Shows a widget. A result with `error: true` is not shown. |
| `done` | `response_text` | Ends the reply. The server has saved it. |
| `error` | `code` (`AGENT_ERROR`, `STREAM_ERROR`), `message` | Ends the reply. The app shows its own localized text for `code`. |

A frame name the app does not know is skipped and logged. A 401 on the stream gets one forced
refresh, then ends the session. A 403 `USER_INACTIVE` ends the session. An unknown or foreign
`conversation_id` answers 404; the next message starts a new conversation. A message over 4000
characters is not sent. In the widget host page, a `tools/call` request gets a JSON-RPC error at
once.

**Push.** A push `data` map has string values. The app reads `route`, `type_key`, `property_id`
and `_meta` (JSON text). It does not read `deep_link`. A push with a `type_key` and no `route`
opens the place of that type (`visit_reminder` opens Visits).

**Links.** The app parses `https://360ghar.com/...` property links and the custom scheme forms
`ghar360://property/{id}`, `ghar360://p/{id}` and `ghar360://360ghar.com/p/{id}`
(`DeepLinkService.propertyPathForUri`). The backend sends no custom scheme link for this app.
`ghar360://login-callback` is the OAuth callback and is never a property link.

## Backend endpoints the app does not call

`POST /leads`, `/swipes/undo`, `/swipes/batch-remove`, `/swipes/stats`,
`/properties/recommendations`, `/visits/{id}`, `/visits/upcoming`, `/visits/past`, `/upload`,
`/notifications/me`, `/users/me/auth-state`, `POST /versions/check`, `/auth/delete-account`.
The app deletes an account with `DELETE /users/me`.

## Decisions and open items

| Item | State |
|---|---|
| App update source (`app-core-8`) | The app reads release data from Firebase Remote Config. `AppVersionCheckRequest` (`app`, `platform`, `current_version`, `build_number` as an integer) is the typed body for `POST /versions/check` and is not sent. Switching the source needs a product decision. |
| Auth gate (`app-core-7`, `be-user-26`) | The app derives the profile gate on the device. It does not call `GET /users/me/auth-state`. `UserModel` reads `role`, `phone_verified` and `email_verified`. |
| `ghar360://` property links (`r2-notify-realtime-2`) | Parsed. `DeepLinkService.propertyPathForUri` accepts `ghar360://property/{id}`, `ghar360://p/{id}` and the https form with the scheme swapped; `deep_link_service_test.dart` covers them. The backend does not send them yet. |
| Corrupt legacy store (`r2-client-caches-0`) | Kept as a recoverable startup failure, as `docs/persistence.md` describes. |

## Fixtures and enums

`tool/api_fixtures.py` validates sample data through the backend's response models and writes
`test/fixtures/api/<group>.json` (`mode="json"`, as FastAPI does). It also writes request-body
limits, the operation table and the key list of every response schema from `docs/openapi.json`.

```bash
uv run --project ../360ghar-backend python tool/api_fixtures.py
python3 tool/gen_enums.py
dart run build_runner build --delete-conflicting-outputs
flutter test test/contract
```

`tool/gen_enums.py` reads `contract-audit/enums.json` (or an OpenAPI document with
`--source`). It writes `wire_enums.dart` and `test/fixtures/api/enums.json`. Run it after the
backend enum lists change. `test/contract/enums_contract_test.dart` compares the two.

`test/contract/` has five files: `enums_contract_test.dart`, `error_contract_test.dart`,
`operations_contract_test.dart`, `response_contract_test.dart` and
`stream_and_push_contract_test.dart`. When a backend schema changes, regenerate the fixtures and
run the contract tests.
